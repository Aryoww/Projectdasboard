SOP-EMS-ENG-2026-V1.0 BAB 2: EKSEKUSI HARI SENIN

BAB 2: Panduan Langkah Eksekusi Hari Senin di Electrical Room

Hari Senin adalah momentum kritis pertama untuk membuktikan bahwa penarikan data dari Electrical Room A (yang kabel Ethernet-nya sudah terhubung) dapat terealisasi secara nyata. Urutan tahapan wajib yang harus dikawal di lapangan:

Fase A: Prosedur Keselamatan Kerja (Safety First) di Gardu 20kV

1. Izin Masuk & APD Lengkap: Pastikan memakai helm safety, kacamata pelindung, sepatu safety tahan tegangan (ESR), dan pakaian kerja standar. Jangan menyentuh busbar kubikel 20.000V.
2. Area Kerja Terisolasi: Aktivitas penarikan data hanya dilakukan pada Low Voltage Compartment tempat modul meter digital dan terminal komunikasi berada.

Fase B: Pengujian Fisik Kabel Ethernet & Sambungan Switch IT

1. Inspeksi Kabel UTP: Pastikan kabel LAN Cat6 terpasang rapi di dalam conduit pelindung. Pinout RJ45 standar T568B tidak longgar.
2. Status LED Switch: Periksa port switch IT tempat kabel dicolokkan. Pastikan lampu Link (hijau solid) dan Activity (oranye berkedip) menyala.
3. Pengetesan Panjang Kabel: Pastikan panjang kabel di bawah 90 meter agar tidak terjadi attenuasi sinyal yang memicu packet loss berkala.

Fase C: Konfigurasi Jaringan IP Bersama Tim IT

1. Alokasi IP Statis: Gunakan IP Address statis permanen beserta Subnet Mask dan Default Gateway dari tim IT.
2. Uji Ping Latency: Jalankan perintah ping -t [IP_Gateway]. Latency harus stabil di bawah 5 ms tanpa ada 'Request Timed Out'.
3. Port Whitelist: Pastikan port 502 (Modbus TCP) dan port HTTP 80/443 telah di-whitelist di switch IT.

Fase D: Pengujian Akuisisi Data Perdana (Test Read Polling)

1. Software Tester: Gunakan utility tool seperti Modbus Poll atau skrip penguji untuk membaca Holding Registers meter.
2. Verifikasi Parameter Dasar: Uji baca Tegangan V L-N, Arus Ampere per Fasa, dan Daya Total kW.
3. Logging Kontinu 30 Menit: Jalankan pembacaan data otomatis setiap 5 detik selama 30 menit untuk menguji stabilitas transfer.

SOP-EMS-ENG-2026-V1.0 BAB 3: VALIDITAS DATA (ZERO ERROR)

BAB 3: Protokol Memastikan Validitas & Integritas Data (Zero Error)

Salah satu masalah terbesar dalam proyek IoT industri adalah munculnya data semu (garbage data) karena rasio pengali salah, urutan byte terbalik, atau register tertukar. Metode berikut wajib diterapkan untuk memastikan data 100% valid:

1. Metode Komparasi Sinkron 3 Titik (Three-Point Verification)

Titik Uji Lokasi Pengecekan Parameter Wajib Dicek Toleransi Deviasi
Titik 1: Fisik Panel Display LCD Power Meter di pintu panel gardu Tegangan (V), Arus (A), Daya Aktif (kW), Cos φ Referensi Acuan Utama (0.0%)
Titik 2: Gateway IoT Web management portal / Raw log gateway Nilai register mentah sebelum diproses backend Harus sama persis dengan Titik 1
Titik 3: Dashboard Web Layar Dashboard Telemetri PT Musashi Nilai hasil kalkulasi, grafik kurva beban, akumulasi kWh Maksimal selisih ±0.2%

2. Verifikasi Rasio Current Transformer (CT) & Potential Transformer (PT)

• Formula Rasio CT: Arus Aktual = Pembacaan Sinyal Sekunder (0–5A) × (Arus Primer CT / Arus Sekunder CT). Contoh: CT 400/5A memiliki faktor pengali 80.
• Formula Rasio PT: Tegangan Aktual = Tegangan Sekunder (100V) × (Tegangan Primer PT / Tegangan Sekunder PT). Contoh: PT 20.000V/100V memiliki rasio pengali 200.
• Tindakan: Catat nameplate CT dan PT di ruang gardu dan periksa menu setup meter Schneider untuk memastikan rasio sudah terkunci (locked).

3. Validasi Power Factor (Cos φ) dan Polaritas CT

• Arah Aliran Daya: Nilai kW harus bernilai positif (+) saat beban menyala. Jika negatif (-), berarti polaritas kabel sekunder CT (S1 dan S2) terbalik.
• Kewajaran Power Factor: Normal pada beban industri motor adalah 0.85 hingga 0.98 lagging. Jika di bawah 0.5 abnormal, periksa urutan fasa R-S-T.

Pengaturan Byte Order (Endianness) & Polling

• Big-Endian Float (ABCD): Schneider menggunakan format High Word First. Pastikan parser dashboard diatur ke mode Big-Endian.
• Interval Polling: Gunakan 5–10 detik untuk parameter instan (kW, V, A, PF), dan 60 detik untuk akumulasi kWh kumulatif.

BAB 9: Matriks Troubleshooting Lapangan (Failure Modes & Mitigation)

Dalam implementasi telemetri kelistrikan, berbagai kendala lapangan pasti akan ditemui. Matriks berikut adalah panduan diagnosa cepat dan solusi tuntas yang dapat langsung diterapkan saat menghadapi kendala:

Gejala Masalah Lapangan Akar Penyebab (Root Cause) Langkah Verifikasi Teknis Solusi & Tindakan Korektif
Gateway Timeout / Data Tidak Masuk 1. Catu daya adaptor mati.
2. Port switch IT disabled.
3. IP bentrok (IP Conflict).		 • Cek lampu LED power gateway.
• Jalankan ping berkelanjutan.
• Lepas kabel LAN dan ping IP tersebut.		 Ganti ke PSU 24V DC industri, pasang di stop kontak panel baru, minta tim IT mengunci MAC address statis.
Angka Daya (kW) Terbaca Negatif (-) Polaritas kabel sekunder CT fasa terbalik arah. Periksa tanda titik/panah CT (P1 menuju sumber PLN, P2 menuju beban pabrik). Balik sambungan kabel sekunder S1 dan S2 pada terminal blok meter Schneider.
Angka Daya Jauh Lebih Kecil / Besar Setting rasio CT / PT di meter belum disesuaikan dengan fisik lapangan. Bandingkan menu konfigurasi meter dengan nameplate fisik CT (misal 500/5A tapi terset 100/5A). Masuk ke menu password meter Schneider, sesuaikan CT Primary dan Secondary ke nilai yang benar.
Angka Terbaca Nilai Raksasa Tak Wajar Endianness byte order pada driver parser Modbus terbalik. Bandingkan raw hex buffer terhadap standar IEEE 754 float. Ubah konfigurasi pembacaan dari Little-Endian (CDAB) ke Big-Endian (ABCD) pada skrip parsing.
Sering Putus-Nyambung (Intermittent) Interferensi elektromagnetik (EMI) atau resistor terminasi ketiadaan. Periksa jalur kabel LAN/RS485 apakah menempel pada kabel power 20kV. Pasang resistor terminasi 120 Ohm di meter ujung, pisahkan jalur konduit sejauh min. 20 cm.

Golden Rules Penanganan Troubleshooting:

1. Jangan Mengubah Wiring Saat Bertegangan: Selalu gunakan multimeter penguji sebelum menyentuh terminal kabel.
2. Catat Setiap Perubahan Parameter: Dokumentasikan setiap perubahan IP, Slave ID, atau rasio CT.
3. Simpan Backup Konfigurasi: Backup file konfigurasi gateway konverter dan database dashboard secara berkala.
